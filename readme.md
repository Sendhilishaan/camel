### camel

A from-scratch autograd deep learning library, with the numerical kernels written in C/CUDA (naive + Apple SIMD + Metal + CUDA) and the autograd engine, models, and training layered in Python on top. Even the array type is from scratch: `CamelArray` (python/camel/array.py) is a small numpy-free ndarray clone, so the only C-boundary dependency is a raw ctypes buffer.

**Currently:** a set of primitive kernels: matmul, bias-add, subtract, hadamard, mean, tanh, relu, and fused softmax + cross-entropy, each with a hand-written forward and backward, verified against numerical gradients. Every kernel has four backends: naive float64 C, Apple `<simd/simd.h>` (src/ops/prim_simd.c, two doubles at a time), Metal (src/ops/prim.metal), and CUDA (src/ops/prim_cuda.cu). SIMD and Metal are Darwin-only; naive builds on Windows/macOS/Linux, CUDA on Windows/Linux with NVIDIA hardware. Both GPU backends use float32, with conversion at the `Vbuf` boundary.

`camel.ops.Ops` picks a backend at runtime (`Ops.set_backend(...)`, or the `CAMEL_BACKEND` env var), defaulting to simd wherever it was built and naive elsewhere. GPUs are opt-in; `Ops.metal_device_available()` / `Ops.cuda_device_available()` probe for a working device. `Vbuf` lazily caches an owned GPU buffer, invalidated by a mutation counter shared by `CamelArray` reshape views, and materializes float64 data only when the CPU side is accessed. Forward, backward (including gradient accumulation on fan-out nodes), and all optimizer steps dispatch through this cache. Weights, gradients, and optimizer state stay on the GPU; scalar loss/upstream-gradient values cross to the CPU where the existing interface needs them. Changing backends preserves the buffer's original owner for read/free.

On top sits a reverse-mode autograd engine: a define-by-run Tensor that records a computation graph and backpropagates through it. Above that, a small nn layer (Module, Linear with He init, MLP), SGD with momentum, AdaGrad, RMSprop, Adam, plus DataLoader and k_fold_split for mini-batching. Enough to build, differentiate, and train a small MLP end to end, for regression or classification.

This is inspired by [tinygrad](https://github.com/tinygrad/tinygrad) for the small, composable core, and PyTorch's torch.autograd.Function for the op structure: every op is a class with forward/backward staticmethods and a Context (ctx) that saves what the backward pass will need.


CUDA uses shared-memory tiled matmul (including backward's implicit transposes), parallel mean/softmax reductions, and fused optimizer kernels. The staging and resident entry points mirror Metal, using float32 and no cuBLAS dependency. `make cuda` builds the Linux CUDA library; `CUDA_ARCH` defaults to 120 for RTX 50-series (CUDA 12.8+), with PTX included for forward compatibility. CUDA errors become Python `RuntimeError`s, and `Ops.synchronize()` waits for completed work when benchmarking. `python/tests/cuda_check.py` checks staging/resident parity, numerical gradients, optimizer state, cache invalidation and backend switching; `examples/train_sin_cuda.py` runs the same small MLP as the Metal example.

**CNNs, CUDA and naive review steps:** `nn.Conv2d`, `nn.MaxPool2d` and `nn.Flatten` now connect image tensors to the existing Linear/MLP layers. Inputs are contiguous `(N, C, H, W)`, convolution weights `(out_channels, in_channels, KH, KW)`, and bias `(1, out_channels)`. Conv2d uses cross-correlation, optional bias, integer/pair stride and symmetric zero-padding; dilation and groups are both 1. MaxPool2d uses integer/pair windows and strides (default stride = window), no padding, floor output sizing, and the first maximum in row-major order for ties. The first NaN in a window propagates. Its backward pass routes gradients through cached int32 winning indices and sums contributions from overlapping windows.

The CUDA kernels are direct loops with one writer per gradient element, for a simple, deterministic first implementation. The naive C kernels use float64 nested loops and accumulate each output's gradient contributions into the input, weight and bias gradients. They build with the ordinary CPU library, without CUDA. Native CNN entry points overwrite their output buffers, validate dimensions and pooling indices, and report invalid arguments as Python `RuntimeError`s. Direct C callers must provide correctly sized, distinct output buffers and can inspect `camel_naive_get_last_error()` after each call.

`Vbuf`, elementwise ops and optimizers retain arbitrary-dimensional shapes. Flatten/reshape copies data so each output keeps independent ownership; CUDA uses a device-to-device copy with no CPU materialization. Select `Ops.set_backend("naive")` or `Ops.set_backend("cuda")` for CNNs. CNN dispatch on SIMD/Metal explicitly raises `NotImplementedError` at this review step; existing matrix operations still work on all their original backends.

`python -m tests.cnn_naive_check` runs the CPU CNN suite; `python -m tests.cnn_cuda_check --require-device` runs the CUDA suite (set `PYTHONPATH` to `python` first). They share mathematical contracts in `python/tests/cnn_checks.py`, using tiny synthetic tensors, independent float64 references, hand-calculated examples, finite differences, full CNN graph gradients and error/lifetime checks. Backend-specific checks cover CPU float64 precision and output overwrites, CUDA staging/resident parity, and optimizer updates/state. CPU finite differences use eps=1e-6; CUDA uses eps=1e-3 for float32 rounding. No downloads, benchmarks or dataset training. `examples/cnn_naive.py` and `examples/cnn_cuda.py` are two-image forward/backward demonstrations.

`nn.CNN` lives alongside `nn.MLP` in `python/camel/nn.py`. `CNN(1, [4, 8], 2, image_size=8)` builds two convolution blocks with 4 then 8 channels and a two-class linear output. Each block is a 3x3 convolution with padding 1, an activation (ReLU by default), and 2x2 max pooling. `image_size` is an integer or `(height, width)` pair used to size the classifier after pooling. Like MLP, it accepts a list of Function classes through `activations`, with one per convolution. Outputs are logits, ready for `softmax_xent`.

`python examples/train_cnn.py` trains `CNN(1, [4], 2, image_size=8)` on synthetic 8x8 images of noisy horizontal and vertical bars, with 32 training images and 16 separate validation images. It uses cross-entropy and Adam in batches of 8 for 30 epochs, printing training loss and validation loss/accuracy. Set `BACKEND` at the top of the file to `"naive"` or `"cuda"`; the other training settings are there too. No downloads or external Python packages are needed. Build the native library and set `PYTHONPATH` to `python` as above before running.
