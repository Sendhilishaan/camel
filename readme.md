### camel

A from-scratch autograd deep learning library, with the numerical kernels written in C (naive + Apple SIMD + Metal now, CUDA later) and the autograd engine, models, and training layered in Python on top. Even the array type is from scratch: `CamelArray` (python/camel/array.py) is a small numpy-free ndarray clone, so the only C-boundary dependency is a raw ctypes buffer.

**Currently:** a set of C primitive kernels: matmul, bias-add, subtract, hadamard, mean, tanh, relu, and fused softmax + cross-entropy, each with a hand-written forward and backward, all verified against numerical gradients. Every kernel has three backends: naive, Apple `<simd/simd.h>` (src/ops/prim_simd.c, two doubles at a time), and Metal (src/ops/prim.metal, GPU compute kernels operating on float32 since MSL has no double - `Vbuf.to_float32()`/`from_float32()` handle the conversion). All three are Darwin-only. `camel.ops.Ops` picks a backend at runtime (`Ops.set_backend(...)`, or the `CAMEL_BACKEND` env var), defaulting to simd wherever it was built; metal is opt-in since it needs a real GPU device at runtime (`Ops.metal_device_available()` probes for one without crashing). On top sits a reverse-mode autograd engine: a define-by-run Tensor that records a computation graph and backpropagates through it. Above that, a small nn layer (Module, Linear with He init, MLP) and a full optimizer suite: SGD with momentum, AdaGrad, RMSprop, and Adam; enough to build, differentiate, and actually train a small MLP end to end, for regression or classification.

**Next:** mini-batching and a real dataset (MNIST), a CUDA backend behind the same kernel interface, and later CNNs and attention.

This is inspired by [tinygrad](https://github.com/tinygrad/tinygrad) for the small, composable core, and PyTorch's torch.autograd.Function for the op structure, every op is a class with forward/backward staticmethods and a Context (ctx) that saves what the backward pass will need.
